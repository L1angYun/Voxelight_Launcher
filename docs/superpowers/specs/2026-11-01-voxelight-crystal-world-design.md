# Voxelight 结晶世界背景设计

日期：2026-11-01  
状态：用户已定稿  
修订：2026-11-02 用户明确取消完全档的 30/60 FPS 上限；动态画面随浏览器 rAF 刷新，停绘与自动降档规则保留。
范围：全局世界背景 `WorldScene`、它与启动状态的连接、相关设置项和测试  
参考代码：`docs/superpowers/reference/2026-11-01-crystal-world-concept.html`（已确认观感的单文件概念实现）

## 1. 意图

用户对现有背景的判断是：想法很好，但压迫感太强，潜在的视觉震撼没有展现出来。

本次要达到的结果：

- 背景不再压住界面，窗口上半部分有开阔的留白。
- 背景有真实纵深和明暗跨度，单看画面就有冲击力。
- 背景表达真实状态，启动游戏时用户能看到世界随进度发生变化。
- 设计语言继续以 `E:\CodeX\design-systems-main` 的点阵 Lattice 为主要参照。

## 2. 已确定的决定

| 决定 | 内容 |
|---|---|
| 默认外观 | A · 点阵：地平线场景 + 点阵材质 |
| 保留的场景 | 地平线（A）、山体（B），都进入产品 |
| 保留的材质 | 点阵、实体 |
| 放弃的方向 | C 克制修正 |
| 现有方块墙 | 不保留，也不做兼容；新背景可以完全重写 |
| 信号色 | 继续使用 `--accent`（默认绿色），包括用户自定义强调色；不改成 Lattice 的橙色，不增加第三种信号色 |

默认值适用于新安装和升级用户，与 `effects` 默认“完全”的做法一致。

这两个设置只影响背景，不改变 `2026-10-26-voxelight-liquid-ui-design.md` 第 1 节拒绝的“可切换皮肤”：玻璃、控件、排版和主题仍然只有一套。

### 与 2026-10-26 设计的关系

该文档继续有效，下列要求直接约束本设计：

- 文字后方必须有稳定的 scrim，不能依赖背景明暗碰巧可读（第 132、230 行）。
- `effects: "lite" | "full"`，系统减少动态优先（第 265–284 行）。
- 任何时刻只有一个主要运动焦点（第 306 行）。

有一处调整：该文档把 Lattice 分配给数据型组件，把首页场景分配给 Overture。本设计让世界背景使用 Lattice 的粒子物理，理由是它在这里同样表达真实数据（启动进度）。重要时刻的克制原则不变。

## 3. 视觉设计

### 3.1 三种状态

世界中的每个位置都处于三种状态之一。状态有固定含义，不作装饰。

| 状态 | 画面 | 含义 |
|---|---|---|
| 气 | 光点随 ABC 流场飘散 | 正在变化：开场、切页、融化 |
| 点 | 光点落在地形上 | 待命，世界的常态 |
| 晶 | 实体方块 | 已就绪：角色脚下、已完成的进度 |

### 3.2 场景与材质

两个场景共用地形算法和渲染器，只有地形参数、相机和掩膜不同。

| | 地平线 | 山体 |
|---|---|---|
| 相机 | 低机位，看向地平线，上方约 40% 为天空 | 高机位俯视右侧山体 |
| 实体位置（点阵材质） | 角色脚下一小块 | 山体核心，向外渐变成小方块、光点 |
| 内容页 | 机位升高、压暗 | 机位升高、压暗；构图效果在实施中单独验收 |

实体材质下所有位置都是方块，没有粒子层，也是不支持浮点渲染目标时的回退。

### 3.3 状态表现

| 产品状态 | 世界表现 |
|---|---|
| 空闲 | 地形缓慢呼吸，云影移动；点阵材质下只有角色脚下结晶 |
| 准备中 | 结晶前沿从角色脚下推向地平线，半径由真实进度决定 |
| 运行中 | 世界全部结晶，压暗；淡出完成后停止渲染 |
| 取消、失败、结束 | 结晶从地平线退回，恢复空闲 |

失败的说明继续由现有界面提示负责，背景不单独表达错误。

### 3.4 开场

- 字标 VOXELIGHT 由点汇聚而成，再落成大地。沿用 Lattice 的 5×7 点阵字形。
- 每次打开应用最多播放一次，只在首页播放，全程不超过 2.5 秒。
- 导航和启动按钮从第一帧起可用；标题区在字标散开时淡入。
- 单击或开始启动游戏时立即结束开场。
- 精简档、减少动态或背景不可用时跳过。
- 字标设为 `aria-hidden`，产品名继续存在于 DOM 中。

### 3.5 交互

- **移动鼠标（所有页面）：** 推开、旋转附近的点，并留下短暂结晶痕迹。
- **单击空白处（仅首页）：** 产生冲击波。
- **按住空白处（仅首页）：** 局部融化，松开后恢复。

单击和按住只在事件目标不是控件、文字或窗口拖动区时生效，不能干扰文字选择和窗口拖动。背景本身继续 `pointer-events: none`，沿用现有的窗口级监听。

### 3.6 色彩与光

- **深色主题：** 场景底色用场景内变量 `--world-ink: #07080b`，点和文字色用骨白 `#ece7da`。不修改全局 `--bg-base`，避免影响其他页面的表面层级。
- **发光：** 遵守 Lattice 的“发光来自能量”，静止的点不使用信号色，运动、结晶前沿和融化才使用 `--accent`。
- **天空：** 点阵材质下只有淡点阵；实体材质下保留一层地平线雾。后者是对 Lattice “不用渐变”的有意偏离。
- **方块例外：** Lattice 要求“可见之物都由点构成”，本设计把方块定义为结晶后的点，这是唯一例外。
- **浅色主题：** 使用 Lattice 纸面世界的做法，深色点、普通混合、无辉光，雾色取 `--bg-base`。浅色观感尚未验证过，需要单独做视觉验收。

### 3.7 可读性

- 首页文字区增加局部 scrim，并在开场、结晶前沿经过、运行中三种画面下验证。
- 内容页文字继续放在玻璃或实色面板上。
- 验收标准：正文对比度不低于 4.5:1，大标题不低于 3:1，按实际像素在最不利帧测量，深浅主题都要通过。

## 4. 架构

现有 `WorldScene.tsx` 约 1000 行 Canvas 2D 代码，整体重写，不保留旧方块墙的属性、常量、数据属性或行为。唯一的外部调用方 `App.tsx` 随之更新；只在测试中被使用的 `OvertureScene.tsx` 一并删除。

```
App.tsx ── useLauncher ──> deriveWorldState ──> <WorldScene phase fraction page scene material>
                                                        │
                                                  worldDirector（目标值）
                                                        │
                                                  renderer（WebGL2 各通道）
```

模块放在 `src/components/world/`：

| 模块 | 职责 | 依赖 |
|---|---|---|
| `deriveWorldState.ts` | 把 `busy`、`progress`、`running`、`gamePid` 转成场景状态和进度比例 | 纯函数 |
| `worldDirector.ts` | 根据状态、页面、场景、材质算出相机、结晶半径和曝光目标，并逐帧推进弹簧 | 纯逻辑 |
| `camera.ts` | 相机矩阵、鼠标射线与地面求交 | 纯函数 |
| `wordmark.ts` | 把字标栅格化成粒子目标 | 纯函数 |
| `qualityTier.ts` | 根据能力和帧时间选择档位 | 纯逻辑 |
| `renderer.ts` | WebGL2 上下文、帧缓冲、各通道、上下文丢失与释放 | WebGL2 |
| `shaders.ts` | GLSL 源码 | 无 |
| `WorldScene.tsx` | React 外壳：画布、观察器、指针事件、暂停控制 | 以上全部 |

渲染通道：

1. **地形：** 计算高度、阴影和热度，写入纹理。
2. **粒子模拟：** 仅点阵材质，使用位置和速度两张浮点纹理（弹簧 + ABC 流场）。
3. **场景绘制：** 天空、实例化方块、粒子。
4. **后处理：** 辉光与合成；浅色主题关闭辉光。

不引入 three.js。项目现有依赖只通过 skinview3d 间接使用它，而场景所需的功能用原生 WebGL2 足够，已在概念验证中确认。

### 4.1 状态推导

`deriveWorldState` 的规则：

- 存在运行中的游戏（`running.length > 0` 或有 `gamePid`）时为运行中；这是全局判断，不依赖当前选中的实例。
- 否则 `busy === "game.prepare"` 时为准备中，其余为空闲。
- 进度优先取 `bytesCompleted / bytesTotal`，其次 `completed / total`。
- 同一次准备内进度只增不减，避免阶段切换时前沿后退。
- 总量未知时前沿缓慢推进，上限 15%。
- 进入运行中时，前沿在 600ms 内推满。

背景状态不再写死为 `idle`（当前在 `App.tsx:38`）。从任意页面启动，背景都有反应。

### 4.2 设置与持久化

新增两个配置字段：

```ts
worldScene: "horizon" | "massif";     // 默认 horizon
worldMaterial: "lattice" | "solid";   // 默认 lattice
```

需要修改 `src/lib/launcher.ts`、`src-tauri/src/models.rs`、`src-tauri/src/storage.rs`（旧配置补默认值）、`AppearanceSettings.tsx` 和中英文语言包。

切换立即生效，不重启、不丢页面状态。粒子会被流场带起再落到新形态上。

## 5. 档位与降级

| 条件 | 表现 |
|---|---|
| 完全档，粒子预算通过 | 65,536 点，160×160 方块，DPR 上限 1.5 |
| 完全档，帧时间超预算 | 先降 DPR 到 1.0，再降到 25,600 点、110×110 方块 |
| 不支持浮点渲染目标 | 使用实体材质，设置中保留用户选择并说明原因 |
| 精简档、减少动态、高对比 | 渲染一帧静态画面，不模拟粒子，无开场和鼠标交互 |
| 无 WebGL2、上下文丢失且恢复失败 | 静态 CSS 底色和点阵，启动功能不受影响 |

- **帧率：** 按 2026-11-02 用户决定，完全档不再设置 30/60 FPS 上限，随浏览器 rAF 刷新。CPU/GPU 耗时与帧间隔分别记录；静态、隐藏和游戏运行后的停绘规则仍优先。
- **自动降档：** 连续 2 秒平均帧时间超过预算时触发，会话内不自动升回，不写入配置。
- **暂停：** 窗口隐藏、场景不可见、Overture 演出中暂停（沿用现有逻辑）。
- **游戏运行中：** 淡出后完全停止渲染，把 GPU 让给游戏。

## 6. 测试与验收

### 单元测试

- `deriveWorldState`：运行优先级、进度只增不减、总量未知、取消和失败回到空闲。
- `worldDirector`：各状态与页面的目标值。
- `camera`、`wordmark`、`qualityTier`：纯函数和降档路径。
- `WorldScene.tsx`：挂载与卸载释放资源、无 WebGL2 时降级、暂停时不申请帧。

`WorldScene.test.tsx`（844 行）绑定了立方体参数，按新结构重写。

### 端到端测试

`global-glass`、`round6-acceptance`、`round12-runtime-probe`、`round15-runtime` 四个文件引用了 `.world-scene__cube-canvas` 或立方体行为，要改为新画布，并重新定义断言：

- 所有页面背景都有可见像素，玻璃能透出背景。
- 完全档画面随时间变化；减少动态下画面不变。
- 启动时前沿随进度推进，取消后退回。

### 人工验收

- 1050×720 最小窗口、常用窗口和最大化。
- 深色和浅色主题，两个场景，两种材质。
- 第 3.7 节的对比度测量。
- 反复切页和切换设置后，WebGL 上下文、纹理和监听器不增长。

### 性能验收

在本机 RTX 5080 和 Intel 集成显卡上，通过 WebView2 分别记录 1280×720 下的帧时间。

- RTX 5080：完全档 p95 不超过 16.7ms。
- Intel 集成显卡：自动降档后 p95 不超过 33ms。

只记录实测结果，不把这两台设备的结果当作所有低配设备的保证。

## 7. 实施顺序

1. **渲染器：** 建立 WebGL2 骨架和实体材质，完成两个场景，替换旧背景。
2. **粒子层：** 加入点阵材质、三种状态和鼠标交互，然后立即在集成显卡上测量。若 25,600 点档仍不达标，该设备默认回退实体材质，并调整第 5 节的预算。
3. **真实状态：** 接入 `deriveWorldState`，完成启动、运行、取消的表现。
4. **产品化：** 设置项、开场、字体、scrim、浅色主题和降级。
5. **验收：** 完成第 6 节的测试和记录。

## 8. 不在本次范围

- 读取或渲染实例的真实存档。
- 修改玻璃系统。玻璃已使用浏览器真实背景（`GlassSystem.tsx:205`），新背景无需额外接入；只需验证模糊叠加动画后的性能。
- 全局配色或 `--bg-base` 调整。
- 清理 `useGlassBackdrop`。它与本次无依赖，单独处理。
- 声音。
- 更多场景或用户自定义地形。

## 9. 风险

| 风险 | 应对 |
|---|---|
| 集成显卡性能不足 | 粒子层完成后立即验证，有多级降档和实体回退 |
| 动画背景叠加玻璃的 `backdrop-filter` 带来额外开销 | 性能验收在完整界面下测量，不只测背景本身 |
| 笔记本长期开着启动器耗电 | 可选精简档；隐藏和游戏运行时停止，完全档随 rAF 刷新（2026-11-02 用户修订） |
| 点阵近景过密、干扰文字 | 调整点密度和 scrim，并以第 3.7 节的对比度为准 |
| 浅色主题观感未验证 | 第 4 步单独做视觉验收；不达标时浅色主题默认实体材质 |
| 工作区有大量未提交改动，涉及 `WorldScene` 等同一批文件 | 实施前先由用户提交或确认这些改动，再开分支 |
