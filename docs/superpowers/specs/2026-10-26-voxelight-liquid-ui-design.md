# Voxelight Launcher 下一版界面、光学系统与安装体验设计

日期：2026-10-26  
状态：用户已认可设计方向；已并入功能防退化、视觉职责、扩展冗余和全新 UI 的补充要求  
范围：现有 React + TypeScript + Tauri 2 + Rust 主程序，以及 Windows x64 NSIS 安装程序  
基线：0.5.0；本文不预设新版本号

## 1. 意图

Voxelight 首先应该是一个准确、快速、容易理解的 Minecraft 启动器，然后才是一个具有视觉冲击力的桌面作品。

这次重设计要解决四类现存问题：

- 固定侧栏、面包屑、快捷入口和底部账号区重复占用空间，启动主线不够突出。
- 页面标题、宣传式描述、英文眉题和重复状态文案稀释了真正有用的信息。
- 原生标题栏与现有界面割裂，材质、边框、动态和页面分区没有形成统一语言。
- 安装程序只是构建产物，没有成为产品体验的一部分。

产品个性定为 **“方块光学仪器”**：方块世界提供形体与场景，光学仪器提供精确、层次和反馈。它不能做成展示网站、营销落地页或三套可切换皮肤。

## 2. 用户已经确认的决定

- 使用悬浮 Bar、液态玻璃和更有冲击力的效果。
- 借鉴参考站的三种设计语言，但不复制其页面、品牌、主题或滚动叙事。
- 三种语言按职责组合：
  - **透镜 Lens**：悬浮导航、实例选择、启动按钮、弹窗与状态反馈。
  - **点阵 Lattice**：实例关系、资源分类、下载进度、校验、诊断和日志；点阵必须表达真实数据。
  - **序曲 Overture**：首页主场景、首次使用、安装、启动成功和安装完成等少见的重要时刻。
- 日常操作快速克制，较强演出只用于重要时刻。
- 只保留一个 `GlassSystem`、一套材质参数和一套弹簧状态。主程序统一采用一种 WebGL2 光学实现，不混合多个玻璃库或 SVG/WebGL 方案。
- WebGL 不可用时允许静态 CSS 降级；它是兼容措施，不是第二套视觉系统。
- 本版直接准备并实现 i18n，首版完整支持简体中文和 English，包括安装器、用户可见错误、无障碍名称、日期和数字格式。
- 支持跟随 Windows 系统强调色，同时保留 Voxelight 默认色和手动选择。
- 可以参考其他启动器的布局效率，但不能完全照搬它们。
- 特效只保留 **精简 / 完全** 两档，照顾低配设备；完全档启用全部视觉效果。
- 不显示突兀的 Windows 原生标题栏。
- 重做一个有特色的安装程序。
- 删除冗余、重复、空泛或不准确的文字，同一页面不重复解释同一信息。
- 前端 UI 按全新设计实现，不以旧卡片、按钮、页面外壳或局部视觉效果为约束；旧 UI 只作为功能核对清单。
- 声音默认关闭，完整支持减弱动态、减弱透明、高对比度、键盘操作和空状态。

除上述内容外，本文的具体布局、尺寸、配置字段和技术取舍均为设计提案；标为“实现者决定”的内容可在实施计划中确定，不需要再打断用户。

## 3. 目标、非目标与反目标

### 目标

1. 打开应用后，用户能在首屏识别当前实例、运行环境、启动按钮和切换实例的方法。
2. 全局功能、实例功能和账号功能各有明确归属，不通过重复导航弥补分区问题。
3. 用同一套令牌贯通透镜、点阵和序曲，而不是做三套主题。
4. 精简与完全两档共享信息架构和交互结果，只改变渲染预算与演出强度。
5. 中英文、系统主题、系统强调色、无边框窗口和定制安装器在同一版本中验收。
6. 保留现有启动、实例、资源、账号、下载、诊断、多人联机和数据保留行为，并通过防退化验证确认它们在新 UI 中仍然可用。

### 非目标

- 不照搬 Prism、Modrinth、HMCL、GDLauncher 或参考展示站。
- 不同时引入多个液态玻璃库，不提供“自动 / 精简 / 完全”第三档。
- 不新增跨实例同步、房间联机、插件平台、CurseForge、OptiFine 等未承诺功能。
- 不重写历史 0.4.0 / 0.5.0 验收材料，不借重设计改变既有下载信任链、账号授权或 EULA 规则。
- 不为了国际化翻译日志中的原始堆栈、协议响应或许可证正文。

### 反目标

即使构建和测试通过，出现以下情况也算失败：

- 首屏漂亮但启动按钮、当前实例或错误恢复路径不清楚。
- 每个面板都有玻璃、边框、光效和说明文字，导致视觉层级消失。
- 点阵只是随机装饰，进度或诊断图不对应真实状态。
- 精简档变成另一套粗糙界面，或完全档通过隐藏无障碍设置来追求效果。
- 英文只是翻译导航，后端错误、安装器或无障碍文本仍为中文。
- 界面跟随系统强调色后，文字和焦点对比度不合格。
- 无边框窗口失去拖动、缩放、最大化、键盘操作或高分屏能力。

## 4. 已考虑的路线

### 路线 1：液态玻璃作为唯一主角

所有页面都围绕透明、折射和光晕展开。实现直接，但资源、日志、诊断和下载会缺少适合的数据语言，也容易回到“每个卡片都透明”的同质化界面，因此不采用。

### 路线 2：三种语言各自成为完整主题

透镜、点阵、序曲分别形成一套可切换皮肤。展示效果明显，但会产生三套组件状态、排版、无障碍和测试成本，也不符合用户要的一套产品，因此不采用。

### 最终路线：一个 Voxelight，三种职责

导航与操作使用透镜，数据与关系使用点阵，重要时刻使用序曲。它们共享色彩、字号、间距、圆角、弹簧、i18n 和组件状态。用户已选择这一方向。

其他启动器只用于校验信息架构，不构成第四条视觉路线。

## 5. 竞品研究转化为哪些规则

研究依据包括 Prism 官方 `MainWindow.ui`、Modrinth 官方 Play 页面更新说明、HMCL 官方界面文档及本地源码、GDLauncher 官方文档。它们只回答“功能在哪里更容易找到”。

| 观察 | 借鉴的规则 | 明确不借鉴的形式 |
| --- | --- | --- |
| Prism 将全局动作与选中实例动作分开 | 设置、账号属于全局；日志、内容、目录和实例覆盖设置属于当前实例 | Qt 工具栏、右侧动作栏和密集菜单 |
| Modrinth 将 Home 与 Library 合并为 Play | 首页可以展示最近实例，启动与切换实例不应相隔多层 | 直接合并 Voxelight 首页和完整游戏库、其卡片样式 |
| HMCL 将当前实例、账号和全局设置分区 | 当前实例始终有明确上下文；全局游戏默认值与实例覆盖分开 | 固定侧栏、多层导航及其全部页面结构 |
| GDLauncher 区分实例内容、设置与日志 | 实例详情按任务组织，用户不必到全局设置中寻找实例功能 | Overview/Addons/Settings/Logs 的原样复制 |

最终采用 Voxelight 自己的悬浮导航、主场景和实例详情，不复制上述产品的布局或视觉资产。

## 6. 信息架构

### 6.1 全局悬浮 Bar

顶部只保留一条水平悬浮 Bar，不再使用 236px 固定侧栏和重复面包屑。窗口控制与 Bar 共用顶部空间，但视觉上分成两个区域。

主要导航：

- **开始**：当前实例、启动和最近实例。
- **游戏库**：全部实例、创建/导入和实例详情。
- **探索**：在线资源搜索、项目详情与安装到实例。
- **联机**：服务器列表与现有服务端管理。

右侧工具：

- **下载**：任务图标与真实活动数量；有活动任务时显示形状和文本，不只换颜色。
- **角色**：当前账号头像，打开账号与外观页面。
- **设置**：全局设置。

“角色与皮肤”不再占据一级导航；“下载”不再与游戏资源发现混称。一级页面不显示面包屑，只有实例详情、项目详情等二级页面显示返回。

### 6.2 开始

首页是操作台，不是宣传页。

- 主标题为当前 **实例名称**，版本、加载器和 Java 作为一行真实元数据，不再用巨大版本号替代实例身份。
- 主按钮只有一个：**启动游戏**。运行中变为“正在运行”的状态与独立停止动作；准备中显示阶段、进度和取消。
- 实例选择器与启动按钮组成同一个悬浮控制台。账号入口保留在角色工具中，只有账号问题阻止当前操作时才在控制台内出现恢复动作。
- 世界/皮肤场景是主视觉背景，文字区域必须有稳定 scrim，不能依赖某一张图的明暗碰巧可读。
- 下方只保留 **最近实例**，最多显示少量项目；完整管理进入游戏库。
- 删除“管理游戏库”“探索社区资源”等重复快捷卡片，以及英文眉题、欢迎语、宣传语、无操作价值的状态标签。

场景数据源在此明确：沿用并重新编排现有 **原创 WorldScene + 当前账号皮肤/披风预览** 的组合，不读取或渲染所选实例的真实存档。没有账号外观、离线或加载失败时，使用已有原创默认角色并准确标注；场景失败不阻塞启动。这样不需要新增真实世界渲染管线，也不会把示例场景误解为用户的实际世界。

空状态：

- 无实例：主要动作“创建实例”，次要动作“导入整合包”，不显示虚假的“准备就绪”。
- 无账号：允许现有离线流程，不阻塞不需要正版账号的操作；在需要账号的动作处解释原因。
- 外观加载失败：场景仍可操作，显示一次重试，不把默认角色描述成真实账号皮肤。

### 6.3 游戏库与实例详情

游戏库负责实例集合：搜索、排序、视图切换、创建、导入和选择。默认展示真实实例，不额外堆叠全局资源和全局诊断。

实例详情使用同一实例上下文，分为：

- **总览**：版本、加载器、最近运行、目录、备份/克隆/导出等管理动作。
- **内容**：模组、资源包、光影及兼容来源；本地内容与在线探索保持明确来源区别。
- **世界**：存档、世界导入导出与截图。
- **日志**：游戏日志、启动诊断和相关修复动作。
- **设置**：只显示当前实例的 Java、内存、窗口和参数覆盖；全局默认值在全局设置中修改。

危险动作集中在管理菜单，不与启动按钮争夺视觉主次。实例运行中继续执行现有保护规则。

### 6.4 探索

探索只负责发现与获取内容：搜索、来源、游戏版本、加载器、分类、项目详情、版本与依赖。安装前明确目标实例；没有目标实例时提供创建流程。

这里不重复展示下载中心，也不把“安装游戏版本”和“浏览社区资源”写成同一种资源。

### 6.5 联机

保留现有服务器与受管服务端能力，按“服务器 / 服务端”组织。状态必须来自真实查询或进程，不用装饰性在线点代替未验证状态。

### 6.6 下载

下载页是任务中心，不再同时充当资源安装入口和通用运行日志页。

- 活动任务：阶段、已完成/总量、速率（有真实数据时）、暂停、恢复、取消。
- 历史任务：完成、失败、取消及可执行的恢复动作。
- 点阵进度与校验状态来自同一任务数据源。
- 首页可以显示当前任务的精简摘要，完整任务只在下载页展开；两处不重复长篇日志。

### 6.7 角色与全局设置

角色页管理账号、离线角色、正版皮肤/披风和本地预览，明确区分“修改线上账号外观”与“只修改启动器预览”。

全局设置分为 **通用、外观、游戏、Java、下载、关于**。语言、特效、主题、强调色和无障碍位于外观或通用的对应组；实例覆盖不在这里重复。

## 7. 文案规则

- 优先使用用户任务命名：开始、游戏库、探索、联机、下载、角色、设置。
- 删除英文眉题、诗意副标题、重复“欢迎来到/准备出发/创造世界”等宣传式内容。
- 标题回答“这里是什么”，正文只在需要解释后果、限制或下一步时出现。
- 不用标签堆砌状态。能由实例名、图标、进度或按钮表达的信息不再写一遍。
- 状态文案必须来自真实状态，例如“已校验 42 / 128 个文件”，不能写“绝对安全”“全部兼容”。
- 按钮按动作命名：“启动游戏”“取消准备”“上传正版皮肤”，不使用含糊的“确定”“好的”代替关键动作。
- 按钮主次由当前任务决定，不由“下载是正面、删除是负面”的含义决定。危险通过具体动作、影响说明和确认表达，不靠整页红色。
- 空状态只包含一个有用标题、必要的一句原因和一个主要动作；没有可执行动作时不硬加按钮。
- 原始堆栈与远程响应进入诊断详情；用户可见错误先给出可理解原因和恢复动作。

## 8. 统一视觉基础

### 8.1 先建立灰阶层级

在加入强调色之前，先用背景、悬浮层、玻璃层、主文字、次文字和弱文字建立层级。深色与浅色各有一组中性色令牌，不能通过简单反相得到浅色主题。

颜色角色包括：

- `bg-base`、`bg-raised`、`bg-overlay`：页面与浮层。
- `surface-glass`、`surface-solid`：玻璃与需要稳定背景的内容。
- `text-primary`、`text-secondary`、`text-tertiary`：阅读层级。
- `accent-*`：当前强调色及其不同亮度/透明度变体。
- `success`、`warning`、`danger`、`info`：语义状态，每种同时有图标或文字。

强调色只用于当前选择、主要动作、焦点、关键数据和重要时刻。普通卡片不全部加边框；需要边界时优先使用背景差、阴影和间距。

### 8.2 字体与排版

- 使用本机 UI 字体栈，中文优先 Microsoft YaHei UI / Segoe UI 等可用字体，不从网络加载正文文字字体。
- 正文以 13–14px 为主，标题按 16 / 20 / 28 / 40px 等有限层级使用；实例名最多约 40px，不靠超大字号制造层级。
- 次要信息通过字重、间距和位置弱化，不只靠更低透明度。
- 长说明限制行长，并联动行高；正文约 1.55–1.7，紧凑控件约 1.2–1.35。
- 数字进度、文件计数和日志时间使用等宽数字；点阵字体只用于图形，不用于正文或长数字。
- 文本、图标和按钮按基线对齐，不以边界框的几何居中代替视觉对齐。

### 8.3 间距、尺寸与缩放

- 间距采用 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 的有限序列，相关项靠近，不同组拉开。
- 页面内容设置最大宽度，宽屏增加外部留白和场景空间，不把所有文字、按钮和卡片等比放大。
- 在 1050×720 最小窗口内完成所有主要任务；更宽时首页场景与实例网格扩展，设置页正文不无限变宽。
- 常用桌面点击目标约 36–40px，最小不小于 24px；密集日志行可以更小，但其动作仍满足目标尺寸。
- 图片、场景和图形有各自适用尺寸，不用一个固定卡片比例套用所有内容。

### 8.4 图上文字与空状态

- 所有场景文字后方使用渐变 scrim、局部实色或玻璃底色，并分别验证深浅主题。
- 普通正文对比度至少 4.5:1，大字至少 3:1；焦点和关键图形至少 3:1。
- 空、加载、失败、离线、无结果、权限不足分别设计，不用一个“暂无数据”覆盖全部情况。

## 9. 一个 GlassSystem

### 9.1 架构

主程序只实现一个自研 WebGL2 玻璃渲染器，通过统一 `GlassSystem` 管理：

- 一个专用于玻璃的 WebGL2 上下文和根层画布。
- 注册表面的尺寸、位置、圆角、材质预设与弹簧状态。
- 导航、按钮、实例选择器、弹窗和 Toast 的材质实例；它们不是不同玻璃库。
- 同一时钟驱动物理弹簧、着色器参数和 DOM 过渡。
- 文字、输入框、焦点、滚动与点击继续由语义化 DOM 处理。

世界和皮肤场景可以继续使用各自的渲染职责，但不能各自再实现一套“液态玻璃”。

折射背景只来自明确的场景/静态纹理和受控快照，不持续栅格化整个 DOM。关键滚动文字不放在需要实时折射的背景层中。

### 9.2 材质与光

只定义少量尺寸预设，例如 `nav`、`control`、`dialog`、`toast`。预设共享同一折射、边缘高光、色散和阴影参数族，只调整厚度、半径和强度。

- 玻璃承载操作与当前状态，不包住每一块正文。
- 液态形变只用于连续变化，例如选择器移动、弹窗出现、启动状态变化。
- 光用于方向、焦点和完成，不常驻照亮所有元素。
- 高对比度或减少透明时，使用同源不透明令牌，保留相同布局与状态。

### 9.3 降级

WebGL2 不可用、上下文持续丢失或恢复失败时，玻璃层切换到静态 CSS 材质。布局、文字、按钮和全部任务保持可用。保存的用户档位不被改写，也不把兼容降级显示成第三档。

## 10. 精简与完全：只有两档

新增持久化设置 `effects: "lite" | "full"`。中文显示“精简 / 完全”，英文显示“Lite / Full”。

| 内容 | 精简 | 完全 |
| --- | --- | --- |
| 信息架构、功能与反馈 | 完全相同 | 完全相同 |
| 玻璃 | 同一 GlassSystem，低成本采样，状态变化时更新 | 完整动态折射、边缘高光与受控色散 |
| 首页场景 | 静态或低更新频率，关闭环境循环 | 完整场景、光照、环境动态与交互响应 |
| 粒子与氛围 | 关闭 | 开启 |
| 导航与控件 | 短淡入淡出，无视差、弹性拖尾 | 完整弹簧、连续形变、视差和光学反馈 |
| 下载与诊断 | 真实数据点阵，静态/按需更新 | 同一数据点阵，增加流动与映射演出 |
| 重要时刻 | 单次数值/透明度过渡 | 完整光圈、显影、粒子和场景演出 |
| 离屏与后台 | 停止渲染 | 同样停止渲染 |

默认新安装和从 0.5.0 升级都使用“完全”，让所有用户看到本次重设计的完整效果。现有版本没有可映射的独立特效/性能档位，因此不虚构迁移来源；系统减少动态等既有无障碍信号仍优先。低配用户可在设置中直接切换“精简”，切换不重启应用、不丢失页面状态。

精简档在空闲时不运行环境渲染循环；完全档也不能在窗口隐藏、页面不可见或系统锁屏后持续空转。两档都遵循相同的数据更新与任务逻辑。

无障碍不是第三档：

- 系统“减少动态”始终优先，即使用户选择完全，也移除非必要连续运动、视差和强烈缩放。
- 系统“减少透明”或应用内对应设置使用不透明表面。
- 高对比度模式覆盖材质和颜色，但不改变导航与功能。

声音仍是独立设置，默认关闭，不由“完全”自动开启。

## 11. 点阵与序曲

### 三种语言的元素级职责

普通排版、表单、列表和留白是共同基础，不属于第四种视觉语言，也不需要为了“有设计感”而强行添加玻璃、点阵或演出。

| 元素/时刻 | 主导语言 | 明确效果 | 同时禁止的堆叠 |
| --- | --- | --- | --- |
| 悬浮导航、实例选择器、启动按钮 | 透镜 | 连续形变、折射、按压与拖动反馈 | 不再叠加点阵框、粒子和扫光 |
| 实例/资源卡片的悬停、键盘焦点与选中 | 点阵 | 由真实项目身份驱动的点、角标、轨迹或选择框；选中状态有持久形状 | 不再同时缩放卡片、加玻璃光晕和第二层描边 |
| 实例关系、分类、进度、校验、诊断 | 点阵 | 数据点、映射、阶段与异常形状，所有数据可追溯 | 不使用随机背景点阵或仅为好看的假图表 |
| 弹窗、菜单、Toast | 透镜 | 同源材质、进出弹簧与状态连续变化 | 不播放序曲，不给每行内容再套玻璃 |
| 首页场景、首次使用、安装/启动成功 | 序曲 | 光圈、显影、场景与一次性的完成演出 | 演出时不叠加环境粒子、卡片流光和多个运动焦点 |

同一个元素可以在不同状态使用不同语言，但每个状态只有一个主导效果。例如：实例卡片默认使用普通中性表面；悬停/焦点/选中只出现点阵选择框；按下启动按钮时使用透镜形变；启动成功后由序曲接管一次反馈。

“完全”表示所有效果通道都可用，不表示所有效果必须在同一时刻播放。完全档通过场景规模、光学质量、连续响应和关键时刻编排制造冲击；任何时刻只保留一个主要运动焦点。这样既保留震撼视觉，也避免元素堆砌。

### 点阵

- 实例点可以表示版本、加载器、运行或更新状态，但必须能追溯到真实实例。
- 下载点阵可以表示文件队列、完成、失败和重试，数量来自真实任务或有明确归并说明。
- 日志保留等宽文本和原始内容；点阵只辅助定位错误、阶段或分布，不替换可复制日志。
- 状态同时使用形状、线型、图标或文本，不能只靠颜色。

### 序曲

完整演出只用于：

- 第一次进入应用。
- 创建或安装实例完成。
- 游戏从准备进入运行。
- 安装程序完成。

同一成功事件不反复播放；用户切页、重复启动或调整窗口不会重新触发。高频页面切换只使用短过渡。

## 12. i18n

### 12.1 架构

采用 `i18next` + `react-i18next`，语言资源随应用静态打包，避免切换时网络请求和闪烁。首版 locale 为 `zh-CN` 与 `en-US`，使用 stable message key、命名空间和参数插值。

- React 可见文本、`title`、`aria-label`、占位符、空状态和确认对话框全部来自消息资源。
- Rust/IPC 用户错误改为稳定的错误代码与参数；前端翻译原因和恢复动作。原始技术细节仍保存在诊断中。
- 不通过拼接中英文片段构造句子；复数、性别/语序和变量位置由完整消息处理。
- 日期、时间、数字、百分比、文件大小和持续时间使用 `Intl` 与当前 locale。
- 实例名、账号名、文件名、加载器名和远程项目标题保持原文。
- 缺 key 时开发环境报错，生产环境回退到 `en-US` 并记录诊断，不能显示空白。

首次运行读取 Windows 用户界面语言：`zh-Hans`、`zh-CN`、`zh-SG` 映射到 `zh-CN`，其他未支持语言回退到 `en-US`。用户手动选择后持久化，不再被系统覆盖。

### 12.2 安装器

NSIS 注册 SimpChinese 与 English，首次显示可选择的语言，默认匹配系统。所有自定义页面、按钮、进度、失败、完成和卸载相关新增文本均使用 NSIS 语言字符串。

许可证和第三方通知保留具有法律意义的原文；可以翻译界面标题，不擅自创造“官方中文法律译本”。

## 13. 系统主题与强调色

保留 `theme: "dark" | "light" | "system"`，系统主题变化实时生效。

强调色提供三个互斥来源：

- **Voxelight**：默认品牌色。
- **跟随系统**：读取 Windows 当前强调色，并在系统更改后更新。
- **自定义**：使用现有色板/自定义颜色能力。

新增 `accentSource: "voxelight" | "system" | "custom"`，保留 `accentColor` 作为自定义值。新安装默认 `system`（跟随 Windows 强调色，用户明确要求）；升级配置如果仍使用原默认色 `#b4f17a` 则迁移为 `system`，其他色值迁移为 `custom`，避免改变用户已有选择。

Rust 负责读取 Windows 强调色和通知变化，前端只消费标准化 RGB，不直接读取注册表。原始系统颜色先转换到 OKLCH/等效感知空间，再生成适合当前深浅主题的变体；不能把所有文字直接替换成未经校验的系统色。

焦点、选择和主要动作允许使用强调色边框或描边；普通容器不因此全部获得彩色边框。

## 14. 无边框窗口

主窗口改为 `decorations: false`，保留系统窗口阴影、任务栏、Alt+Tab、Snap 和缩放能力。

- 顶部提供明确的空白拖动区域，控件区域不会误触拖动。
- 双击空白区域切换最大化/还原；最小化、最大化/还原、关闭按钮有本地化无障碍名称。
- 最大化时移除外部圆角和悬浮外边距，内容不能藏到屏幕边缘或窗口控制下方。
- 验证 `WebviewWindowBuilder::from_config(...)` 创建路径，而不只验证静态配置。
- 验证 1050×720、1440×930、1920 宽屏、不同 DPI、鼠标与键盘、拖动和系统吸附。

标题可以保留给操作系统与辅助技术，但不在界面顶部重复显示一条传统标题栏。

## 15. 定制 NSIS 安装程序

安装器延续“方块光学仪器”，但不嵌入 WebGL、React 或另一套动画运行时。使用定制 NSIS 原生控件与同源预渲染光学素材，保证体积、键盘操作和系统兼容性。

流程：

1. **欢迎**：产品标识、一句准确说明、语言选择。
2. **位置**：当前用户默认安装目录和可用空间；不展示无关功能宣传。
3. **选项**：开始菜单/桌面快捷方式等真实选项。
4. **安装**：真实文件阶段与进度，失败给出可读原因。
5. **完成**：序曲式静态光圈/显影素材和“启动 Voxelight”选项。

视觉以同一块“光学方块”从轮廓到显影作为进度叙事；不能让装饰动画阻塞安装，也不能伪造百分比。

继续保留：

- `currentUser` 安装模式，不静默提升权限。
- 现有升级、注册表/卸载信息、许可资源与通知。
- 默认卸载保留用户数据，不复制账号、令牌或个人存档到验收环境。
- Windows x64 构建边界和“未做受信任代码签名”的准确表述。

## 16. 动效与性能验收

- 日常控件反馈目标约 120–180ms；重要演出可以更长，但不阻塞下一步操作。
- 弹簧以物理状态连续更新，切页或反向操作不跳变。
- 精简档空闲时无环境 `requestAnimationFrame` 循环；两档离屏均暂停。
- 反复切页、打开弹窗和切换档位后，WebGL 上下文、监听器和纹理数量不持续增长。
- 在验收机器上分别记录精简/完全的帧时间、长任务、内存与 GPU/CPU 情况；不把一台机器的结果宣传为所有低配设备保证。
- 完全档在参考验收分辨率 1440×930 下以流畅交互为目标；遇到性能问题先调整渲染成本，不删除信息或输入反馈。

本次主要参考环境为 Windows 11 专业版 Insider Preview（build 26220）、WebView2 157.0.4341.16、Intel Core Ultra 9 275HX、约 32 GB 内存、NVIDIA GeForce RTX 5080 Laptop GPU / Intel Graphics。它用于记录实际结果，不作为最低配置声明。

低配验收分为两部分：精简档的渲染预算检查，以及强制无 WebGL2/上下文丢失的兼容测试。当前没有单独的真实低配验收设备，因此不能用高性能机器上的限速或禁用 WebGL 结果冒充低配实机保证；交付记录必须明确这一边界。

## 18. 实现边界与实现者决定

### 全新 UI 与现有代码的关系

- 页面布局、React 展示组件、导航、样式和交互按本文重新设计，不在旧 `App.tsx` 外壳上逐块修补。
- 旧 UI 仅用于核对功能入口、IPC 参数和状态；不把旧卡片、按钮或宣传文案当成新设计的组件基础。
- 继续保留 React 与 Tauri 业务连接、现有 WorldScene/皮肤能力，以及 Motion、Lucide、skinview3d 等仍有明确职责的底层依赖。
- 当前 `MagicCard`、`ShimmerButton` 是项目内局部组件，各只有一处使用，不属于需要保留的外部 UI 框架。新 UI 不沿用其光晕/扫光效果，相关调用和无用代码在新组件接通后移除。
- 当前项目没有 Aceternity 依赖。`clsx`、`tailwind-merge` 等工具是否保留由新代码是否实际使用决定；不为了“沿用旧库”保留无用依赖。

### 为后续补全功能预留的架构冗余

- 导航使用注册表，区分 `primary`、`utility`、`contextual` 位置和可见能力，不把页面 ID、图标和权限判断散落在多个组件中。
- 实例详情标签、设置分组、资源类型和下载来源均使用可扩展定义；后续增加数据包、更多加载器、下载来源或实例能力时，不需要重写整个页面。
- 下载任务使用可扩展的阶段/状态模型和稳定错误代码，新增任务类型时复用进度、取消、暂停、历史与 i18n。
- i18n 按功能命名空间拆分，新增功能必须同时提交中英文资源、错误和无障碍名称。
- 配置使用 additive 字段、明确默认值和版本化迁移；新功能不得破坏旧配置读取。
- GlassSystem 只暴露统一表面和效果通道。新功能选择现有视觉职责，不新建私有玻璃、粒子或弹簧实现。
- 能力未完成时不显示空入口或“敬请期待”。架构冗余存在于代码和数据模型中，不表现为视觉留白、闲置卡片或无用标签。

实现者可以在不改变上述用户体验的情况下决定：

- `App.tsx` 的组件拆分边界、路由/页面状态组织和样式模块划分。
- GlassSystem 的着色器细节、纹理格式、采样频率和具体性能优化。
- 复用现有 `motion` 与 WebGL 代码的方式；不新增第二个玻璃或动画体系。
- Windows 强调色读取/事件接线的具体安全 API，以及系统主题/语言读取的 Rust 封装。
- NSIS 自定义页面脚本的具体控件实现与资源生成方式。
- 配置迁移、错误代码目录和 i18n 命名空间的详细文件布局。

实施前先用测试定义：两档特效行为、语言回退、配置迁移、系统色处理、无边框窗口控制和安装器关键流程。实施后必须构建真正的 NSIS 安装包并执行安装/升级验收，不能只交付浏览器截图。
